# Codex Frontend, UI, and UX Capability Inventory

Inventory date: 2026-11-05 (Asia/Dhaka)

This document lists the UI/frontend-related capabilities that are installed or exposed in the current Codex desktop session. It distinguishes four different things that are easy to confuse:

- **Skill**: instruction pack selected by Codex. Invoke explicitly with `$skill-name`, or say `Use the <name> skill`.
- **Plugin skill**: skill supplied by a plugin. Its qualified name is normally `plugin-name:skill-name`.
- **Agent profile**: a specialized prompt bundled by a plugin. ECC contains these files, but they are not all first-class Codex subagents.
- **Plugin command/tool**: an MCP/app operation Codex calls internally. Users normally request the outcome in natural language instead of typing the tool name.

`agents/openai.yaml` inside many standalone skills is interface metadata, not an independent agent.

## Recommended Default Stack

Use this combination for most professional frontend work:

1. **Single end-to-end design toolkit**: `impeccable:impeccable`. It can shape, build, critique, audit, refine, harden, optimize, and visually iterate on marketing or product UI.
2. **New marketing site or landing page**: `impeccable:impeccable` + `$design-taste-frontend` or `$frontend-design`. Choose one supporting aesthetic authority, not every style skill.
3. **Existing UI redesign**: `impeccable:impeccable` + `ecc:design-system`; use Impeccable `critique`, `audit`, `polish`, or a full redesign as appropriate.
4. **Product UI, dashboard, or internal tool**: Impeccable in **Operate** mode + `ecc:design-system` + `$ui-styling` or the relevant framework skill.
5. **Accessibility audit and fix**: Impeccable `audit` + `ecc:accessibility` + `ecc:frontend-a11y` + `ecc:browser-qa`.
6. **React implementation**: `ecc:react-patterns` + `ecc:react-performance` + `ecc:react-testing`.
7. **Motion**: Impeccable `animate`, or `$find-animation-opportunities`/`$improve-animations` for a dedicated audit and `$review-animations` for final review.
8. **Figma handoff**: `figma:figma-design-to-code` for Figma to code; `figma:figma-generate-design` or `figma:figma-generate-library` for code/brief to Figma.
9. **Visual verification**: Impeccable finish review + Browser plugin + `ecc:browser-qa` + `$webapp-testing` or `ecc:e2e-testing`.

## Impeccable Plugin 4.3.1

Status: installed. The `4.3.1` plugin package and its trusted post-edit/stop hook configuration were verified locally. Plugin id: `impeccable@openai-curated-remote`. Qualified skill: `impeccable:impeccable`.

Impeccable is the broadest dedicated UI design toolkit in this installation. It covers websites, landing pages, dashboards, product UI, app shells, forms, settings, onboarding, empty states, responsive behavior, accessibility, performance, typography, layout, color, motion, UX copy, edge cases, and reusable design systems.

### Primary Invocation

```text
Use impeccable:impeccable to audit and improve this interface.
```

The plugin chooses one of four surface modes:

- **Persuade**: landing pages, marketing, campaigns, and pricing.
- **Operate**: dashboards, editors, settings, admin panels, and application workflows.
- **Read**: documentation, articles, guides, help, and changelogs.
- **Experience**: portfolios, galleries, showcases, and artifact-led experiences.

### Impeccable Control Commands

- `impeccable context`: loads `PRODUCT.md`, `DESIGN.md`, surface briefs, platform guidance, and project state once per session.
- `impeccable pin <pin|unpin> <command>`: creates or removes a standalone `$<command>` shortcut.
- `$impeccable hooks on|off|status|ignore-rule|ignore-file|ignore-value|reset`: controls the project design-detector hook.
- `$impeccable doctor`: reports and repairs drift among `PRODUCT.md`, `DESIGN.md`, sidecars, configuration, surface briefs, and hooks.
- Windows launcher: `<Impeccable skill directory>\scripts\impeccable.cmd <verb>`.

### Impeccable Internal Agents

These are real TOML agent definitions bundled inside the skill. Impeccable delegates specialized work to them; they are not intended as independent user-facing commands.

| Agent | Responsibility |
| --- | --- |
| `impeccable_asset_producer` | Produces clean reusable raster assets from an approved visual direction without redesigning it |
| `impeccable_documenter` | Derives `DESIGN.md` and its sidecar from the finished implementation rather than intentions |
| `impeccable_finish_reviewer` | Reviews screenshots, direction contract, approved comp, craft floor, and implementation; returns `recapture`, `rebuild`, `fix`, or `ship` |
| `impeccable_manual_edit_applier` | Applies live-mode copy edits safely to source files with atomic validation |

### Impeccable Automation and Files

- Project context: `PRODUCT.md`.
- Design-system record: `DESIGN.md` and sidecar.
- Surface briefs and visual decision artifacts under `.impeccable/`.
- Desktop/mobile screenshot review with bounded repair passes.
- Optional post-edit design-detector hooks for common UI anti-patterns.
- Live browser variants, manual copy editing, comp measurement, visual diffing, and finish-review gates.

## Browser and Computer-Use Plugins

Status: installed and enabled. Skill: `control-in-app-browser`.

Status: installed as a bundled plugin. Skill: `control-chrome`.

Status: installed and enabled.

## Practical End-to-End Commands

### Audit and fix an existing React product UI

```text
Use ecc:design-system, ecc:frontend-design-direction, ecc:frontend-a11y,
ecc:react-patterns, ecc:react-performance, and ecc:browser-qa.

Audit the current product UI, prioritize findings by user impact, implement the
high-priority fixes using the existing stack, run component and E2E tests, and
visually verify desktop and mobile breakpoints in Browser. Preserve existing
business behavior and report any remaining risks.
```

### Design and build a non-generic landing page

```text
Use design-taste-frontend, frontend-design, emil-design-eng, and imagegen when
visual assets are needed. Infer a product-specific visual direction, avoid
generic AI landing-page patterns, implement the page in the existing framework,
and verify it in Browser at desktop and mobile sizes.
```

### Implement a Figma design accurately

```text
Use figma:figma-design-to-code, then use the relevant framework skill and
ecc:browser-qa. Read the Figma design context, variables, assets, screenshots,
and motion context; implement it with the project's existing components and
tokens; then compare the browser result against Figma at matching viewports.
```

### Accessibility audit

```text
Use ecc:accessibility, ecc:frontend-a11y, and ecc:browser-qa. Audit against WCAG
2.2 AA, keyboard navigation, focus order, screen-reader semantics, contrast,
target size, reduced motion, and error states. Implement fixes and verify with
axe plus manual keyboard interaction.
```

### Motion audit and repair

```text
Use improve-animations to create the prioritized audit, animate to implement the
approved repairs, review-animations for the final review, and Browser to verify
the interactions and reduced-motion behavior.
```

## Known Issues and Selection Warnings

1. `ui-ux-pro-max` is installed incompletely: its `SKILL.md` references a search script and reference database that are missing from the installed directory.
2. Several local skills duplicate ECC skills (`frontend-patterns`, `e2e-testing`, `swiftui-patterns`, `liquid-glass-design`). Prefer the `ecc:` qualified versions so the source and version are unambiguous.
3. Do not stack every visual-style skill. `minimalist-ui`, `industrial-brutalist-ui`, `high-end-visual-design`, and `gpt-taste` encode conflicting aesthetics. Choose one direction per project.
4. Use `design-taste-frontend` primarily for marketing/portfolio/redesign work, not as the main system for dense operational product UI.
5. ECC's Claude-style source commands and agent profiles are useful references, but only the installed skills and migrated command-skills should be treated as native Codex invocations.
6. Impeccable is a complete umbrella workflow. When it is active, add a second style skill only for a deliberate aesthetic specialty; stacking several independent taste systems can produce contradictory rules.
7. Two Figma packages are cached (`17.0.0` and legacy `2.0.13`). Treat `17.0.0` as the active workflow source.
